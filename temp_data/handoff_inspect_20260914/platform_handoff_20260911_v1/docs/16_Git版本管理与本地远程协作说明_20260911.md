# 20JD Git 版本管理与本地/远程协作

## 推荐架构

将“代码版本”和“大体积实验产物”分开同步：

1. 使用私有 GitLab/Gitea/GitHub 作为中央 Git 远程，本地机和训练服务器都是 clone；不把服务器工作目录本身当中央仓库。
2. Git 只跟踪源码、配置、测试、文档、小型 fixture 和数据/模型 manifest。
3. 原始/生成数据、checkpoint、模型、outputs 和回传压缩包使用独立 artifact 目录，每个版本保留 SHA-256 manifest。
4. 只有在中央 Git 明确支持 Git LFS 时，才将必须锁定的小部署模型改用 LFS。

这样可避免将约 6.9 GB 工作区全部塞入 Git，也避免训练产生大量不可合并的二进制变更。

## 分支与职责

- `main`：通过测试的集成基线，设为 protected branch。
- `feature/rul-*`：远程服务器上的常规 RUL 开发。
- `local/data-*`：本地数据生成脚本、数据合同或 manifest 变更；生成数据本身不提交。
- 短期分支经 review 合入 `main`，两台机器都不直接修改 `main`。

远程 RUL 仍遵守 `AGENTS.md`：不修改本地所有的 `health_assessment/`、`RLVsim/` 和原始 `datasets/`，不修改冻结 contract。

## 首次连接中央远程

当私有仓库 URL 已建好后，本地执行：

```bash
git remote add origin <PRIVATE_GIT_URL>
git push -u origin main
```

训练服务器先保留/改名旧工作区，再 clone，不原地覆盖：

```bash
git clone <PRIVATE_GIT_URL> 20JD
cd 20JD
git switch main
```

日常开发：

```bash
git fetch origin
git switch main
git pull --ff-only
git switch -c feature/rul-<task>
# 修改、测试、写 IMPLEMENTATION_REPORT.md
git add <explicit-paths>
git commit -m "feat(rul): <summary>"
git push -u origin feature/rul-<task>
```

本地生成数据前也先 `git pull --ff-only`，生成后只提交生成脚本、配置、schema、manifest 和说明。

## Artifact 同步约定

在两端配置 Git 仓库外的专用目录：

```text
20jd-artifacts/
  datasets/<DATASET_VERSION>/
  models/<MODEL_VERSION>/
  outputs/<RUN_VERSION>/
  returns/<RETURN_VERSION>/
```

每个版本不可覆盖，必须保留产生它的 Git commit、配置、数据/源码 hash、环境和 `SHA256SUMS`。同步后先校验 hash，再更新指向当前版本的小型 manifest。服务器训练记录 `git rev-parse HEAD`，回传时仍运行：

```bash
bash rul_prediction/slurm/package_results.sh <VERSION>
```

将得到的压缩包与 `.sha256` 一起通过 rsync/SFTP 同步。

## 合并前检查

1. `git status` 没有 datasets、checkpoint、outputs、returns 等大文件。
2. 冻结 contract hash 未改变；如必须改动则停止并单独评审。
3. 相关测试通过，任务有新的 `IMPLEMENTATION_REPORT.md`。
4. 模型和输出用新的描述性 VERSION，不覆盖历史结果。
5. 只在候选模型冻结后评估 test 一次。
