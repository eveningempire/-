# 06 寿命预测数据与标签说明

> 状态：RUL-R0 冻结合同 v1.1（2026-09-09；增加全模型合成实验授权，不改变真实数据标签闸门）  
> 适用范围：`rul_prediction/` 的数据审计、标签构造、训练、评价和论文表述。  
> 上游资料：[02_数据集构建说明.md](02_数据集构建说明.md)、[03_健康评估算法说明.md](03_健康评估算法说明.md)、原始报告第六章。

## 1. 本阶段结论

当前 `datasets/generated/system_validation_plan` 共 409 条独立仿真轨迹，其中 210 条为七部件渐进退化轨迹，覆盖循环编号 0、4、8、12、16、20 和 0.5、1.0、1.5 三种退化速率。它可以用于寿命预测代码链路、代理标签和模型原型验证，但不能单独支撑真实物理剩余寿命结论。

原因如下：

1. 当前没有经工程确认的部件失效阈值；
2. 没有原生 `rul_gt`、真实失效循环或 run-to-failure 生命周期；
3. 每条运行是独立仿真，尚无把多个循环绑定为同一寿命个体的 `unit_id`；
4. `Th=cycle_id×480` 表达确定性累计退化，但独立仿真间的随机退化状态会复位；
5. 当前 P1～P17 是仿真隐藏真值，只能用于标签构建和离线评价，不能作为推理输入。

因此，现有数据产生的目标统一称为 **仿真代理 RUL**，字段名使用 `proxy_rul_*` 或在统一表中以 `label_source=simulation_proxy` 显式标识。禁止简称为真实 RUL。

## 2. 预测任务定义

第一阶段任务定义为：在一次任务的决策时刻，使用该时刻及此前已经观测到的部件遥测、运行条件和冻结/交叉拟合得到的健康评估量，预测部件距离预先冻结的代理失效边界还剩多少工作循环。

主要输出：

```text
unit_id, component_id, decision_cycle, event_observed,
rul_cycles, rul_normalized, label_source
```

- `decision_cycle`：作出预测时已经到达的累计循环位置；
- `event_observed`：该寿命单元是否在观测范围内真实越过冻结阈值；
- `rul_cycles`：仅对已观测失效样本为精确值；
- `rul_normalized`：`min(rul_cycles, cap)/cap`，`cap` 必须在查看正式测试结果前冻结；
- `label_source`：`simulation_proxy` 或 `physical_failure_observed`。

当前 409 数据没有合法的 `unit_id + observed failure` 链路，因此默认审计结论必须是 `PROXY_ONLY / NOT_RUN_TO_FAILURE`。不得通过对末端斜率外推、取测试集最差分位点或查看测试结果后调阈值，把未失效轨迹改造成“已观测失效”。

## 3. 标签构造规则

### 3.1 阈值来源

任何阈值必须包含：

```text
component_id, threshold_value, direction, threshold_source, version
```

允许来源：经确认的设计/FMECA 门限、冻结的仿真代理门限、真实试验失效判据。禁止由正式测试集误差最小化反推阈值。没有来源说明时，代码必须停止。

### 3.2 首次越界

对于一个完整寿命单元，只能将实际观测序列第一次越过阈值的循环作为 `failure_cycle`：

```text
rul_cycles = failure_cycle - decision_cycle
```

若观测结束仍未越界，则 `event_observed=false`，精确 `rul_cycles` 保持空值。此类右删失样本不得进入普通 MSE/MAE 回归损失；如后续使用生存分析损失，需另立任务和测试合同。

### 3.3 当前代理实验

在新生命周期数据产生前，可建立 `proxy_rul_v0` 代码原型，但必须满足：

- 只使用预先登记的代理阈值；
- 所有结果目录、图表标题和摘要标明 `simulation_proxy`；
- `healthy`、`fault`、`sensor_fault` 不伪造精确渐进 RUL；
- `compound_degradation` 暂作系统/鲁棒性挑战，不进入首个单部件 BiLSTM；
- 报告有效样本数以独立轨迹/寿命单元统计，不以高度相关的窗口数冒充样本数。

## 4. 输入与泄漏禁令

第一版候选输入为目标部件关键遥测、工况、冻结预测 HI、HI 斜率、置信度和数据质量信息。训练集 HI 必须是冻结外部模型输出或 out-of-fold 输出，不能使用在同一轨迹上拟合后得到的乐观 HI。

以下字段永远不得作为推理特征：P1～P17、`target_factor`、`hi_true`、`rul_gt`、`failure_cycle`、阈值、标签、`rate_*`、故障起止时刻、场景类型、目标部件标签、随机种子及任何未来信息。

`cycle_id`、累计工作时间和累计启停次数默认也不进入主模型，只允许在预注册的“使用量特征消融”中显式开启。即使开启，退化速率和真值字段仍然禁止。

## 5. 数据划分

- 正式生命周期数据按 `unit_id` 整体划分；同一单元的所有循环、窗口和部件序列不得跨集合；
- 当前代理实验只能按完整 `run_id` 划分，且必须注明这是“轨迹级代理实验”，不能宣称 unit-level 泛化；
- validation 只能从训练池按部件/工况确定性划出；
- scaler、特征选择、阈值校准、早停和超参数选择只接收 train/validation；
- test 在全部方案冻结后只评价一次；
- 任何按窗口随机划分的实验一律无效。

## 6. 正式生命周期数据最低合同

后续 `rul_v1` 至少应保存：

```text
unit_id, run_id, component_id, cycle_id, cumulative_work_time,
event_observed, failure_cycle, failure_threshold, threshold_source,
rul_cycles_gt, operating_conditions, random_seed
```

还必须保证同一 `unit_id` 的退化状态跨循环连续、任务条件有受控随机化、失效轨迹与删失轨迹均被保留。正式规模由小样本学习曲线决定，不根据窗口总数决定。

## 7. 代码对应

- `rul_prediction/contracts.py`：术语、字段、特征和输出合同；
- `rul_prediction/data/labels.py`：只认显式阈值，只记录实际越界，不做外推；
- `rul_prediction/data/splits.py`：寿命单元隔离、确定性 validation 和 test 拟合禁令；
- `rul_prediction/tests/`：合同的可执行证据。

## 8. Goal 模式扩展实验的数据边界

为充分利用远程计算资源，现放行在 `synthetic_contract_fixture` 上实现和训练以下算法：纯单向 LSTM、纯 BiLSTM、Transformer–KAN–BiLSTM 及其公平消融、TCN–LSTM–Transformer 多任务教师模型，以及 CNN 蒸馏学生模型。该放行只扩展代码和合成实验范围，不改变本文件前述标签合同。

合成数据必须有确定性的生成器版本、`unit_id`、完整生命周期、预先定义的合成失效机制、按完整 `unit_id` 隔离的 train/validation/test，以及明确的 `label_source=synthetic_contract_fixture`。合成数据不得与 409 快照混合，所有目录、指标、图表和摘要必须标明“合成合同数据验证”，不得形成物理寿命结论。

当前 409 快照仍然是 `PROXY_ONLY / NOT_RUN_TO_FAILURE / NOT_TRAINABLE_ALL_CENSORED`。允许对它进行只读审计、因果序列构造、特征 schema 检查和无标签前向兼容检查；不得生成普通 MSE/MAE 所需的伪精确标签，不得创建训练放行文件，不得把前向输出称为有真值支撑的 RUL 预测结果。
