## 1. 评估目标与总体链路

健康状态评估与故障诊断需要区分：

- **故障诊断**：回答"是否发生故障、故障在哪里、属于什么类型"；
- **健康状态评估**：回答"当前退化到什么程度、变化趋势如何、距离不可接受状态还有多远"。

因此健康评估算法的核心输出是**连续健康指数（HI）**，而不是单纯的离散分类结果。完整链路：

> 仿真遥测数据 → 部件级健康指数 HI → 系统级健康指数 → 退化趋势、风险预警与解释

"单机级"（部件级）的含义：针对液氧泵、氧涡轮、煤油管路、煤油阀、燃气发生器、燃烧室和喷管**分别训练一个部件模型**，七个模型共享代码框架，但输入测点、真值参数、标定参数、特征和 GA 权必须独立。每个模型输出 `HI_i ∈ [0,1]`：1 表示相对健康，数值下降表示相对退化，同时输出状态等级、置信度、主要贡献特征和数据质量标志。

## 2. 算法输入输出契约

### 2.1 部件级输出

每个部件每个评估窗口至少输出：

```text
component_id, timestamp, HI, health_level, anomaly_score,
HI_slope, degradation_onset_flag, confidence, data_quality,
top_contributing_sensors
```

第一版实现的实际输出字段（每部件每窗口）：`run_id, time, mission_phase, component_id, hi_raw, hi_smooth, health_level, confidence, observability, data_quality, top_feature_contributions, model_version`。

### 2.2 系统级输出

至少输出：

```text
timestamp, system_HI, system_health_level, system_risk,
weakest_component, component_contributions,
warning_flag, warning_reason, confidence
```

最终算法不仅要输出健康指数，还要能回答：当前健康程度是多少；是否正在持续退化；哪个部件最危险；哪些传感器支持当前判断；当前评估结果是否可信；是否需要预警、复检或维护。

### 2.3 数据质量前置处理

算法首先应完成：时间同步和重采样、缺失数据检测与插补、异常点识别、滤波和去噪、量纲统一与标准化、工况和任务阶段编码、滑动窗口分段、传感器有效性判断、数据质量评分。数据质量不足时，算法应输出"结果可信度不足"，不能强行判定为健康或退化。（当前实现覆盖了其中窗口化、稳健标准化、质量评分部分。）

## 3. 部件级路线 A：特征工程—CDPCA—遗传算法（CDPCA-GA）

**定位**：可解释基线与工程解释模块。流程：

```text
滑动窗口 → 时域/频域特征提取 → Pearson相关性筛选
→ CDPCA动态降维 → 遗传算法优化主成分权重
→ 加权融合得到HI → 平滑和趋势评价
```

### 3.1 工程约束

1. 按完整轨迹划分训练集和测试集，禁止将同一轨迹的窗口随机分散到不同数据集；
2. 按任务阶段处理，禁止窗口跨越阶段边界；第一版只使用动力段 `phase_2`（140～350 s），`phase_1`/`phase_3` 输出"可观测度不足/低置信度"；
3. 每个部件独立标定健康真值的方向和尺度；
4. 将其他部件的退化轨迹用于检验和约束交叉敏感性（串扰）；
5. 所有标准化、特征筛选、PCA 和 HI 标定参数只能使用训练数据拟合。

### 3.2 真值标定（必须逐部件）

七个部件的健康基准、数值尺度和退化方向不统一（燃气发生器健康轨迹 P5 中位数接近 0，燃烧室因子方向也不同），必须用 `truth_calibration` 模块将每个部件的真值转换为统一相对退化量：

```text
D_true_i(t) = direction_i × [P_i(t) - healthy_reference_i]
HI_true_i(t) = clip(1 - D_true_i(t) / degradation_scale_i, 0, 1)
```

健康基准、方向和退化尺度都只能由训练集估计。当前数据没有经过确认的物理失效阈值，所以现阶段输出应称为"数据集范围内的相对 HI"，不能宣称为绝对剩余寿命比例。

### 3.3 稳健标准化与滑动窗口

- 标准化：只用健康训练轨迹拟合中位数和四分位距，`z = (x - median_healthy)/IQR_healthy`（退化数据不参与健康基准，抗异常点）；参数按"部件、任务阶段、信号"保存。
- 窗口：算法采样率 10 Hz（20 Hz 原始降采样）；窗口 10 s（100 点）、步长 2 s（20 点）；窗口只在同一任务阶段内生成；窗口标签用中心时刻或窗口内真值中位数。

### 3.4 特征工程

当前仿真数据采样率较低、主要反映慢变性能退化，第一版采用可解释、稳定的小型特征库（不无差别生成数千个 Tsfresh 特征）：

**单信号特征**：均值、中位数、标准差、方差；均方根、最大值、最小值、峰峰值；四分位距、偏度、峰度；线性趋势斜率和拟合残差；一阶差分均值/标准差/最大绝对值；一阶自相关系数；总频谱能量、主频、频谱质心；低频段和中频段能量占比。

**多信号关系特征**：两信号窗口均值之差；健康标准化后的响应比值（分母设下限防爆炸）；局部压力与流量的稳态关系残差；核心信号与上/下游信号的相关系数；指令 `fsw_cmd` 与实际响应之间的稳态误差。

**筛选**（只在训练集执行）：删除 NaN/Inf 超限和近零方差特征 → 计算与 `HI_true` 的 Pearson 相关（同时算 Spearman 作诊断）→ 按轨迹分别计算相关性再取中位数（避免长轨迹支配）→ 对相关性 ≥0.95 的冗余特征聚类，每组保留最稳定、物理意义最清楚的一个 → 限制最终特征数 10～30。初始阈值 `|Pearson| >= 0.30`，应通过轨迹级交叉验证确认。

### 3.5 CDPCA 落地定义

论文中的 CDPCA 在本项目明确实现为"多轨迹共享的动态 PCA"：

1. 对筛选后的窗口特征向量构建滞后增广向量 `x_dynamic(t) = [x_t, x_(t-1), ..., x_(t-L)]`；
2. 每条训练轨迹分别构建动态矩阵，使用同一套标准化参数；
3. 各轨迹等权加权后纵向拼接；
4. 在拼接矩阵上拟合**一套共享 PCA 载荷**（不能为每条轨迹单独拟合 PCA，否则主成分坐标不可比较）；
5. 累计解释方差达 95% 时截断，同时设最大主成分数 8；
6. 每个主成分按其与健康真值的相关方向统一符号；
7. 训练和推理使用同一套载荷矩阵。

初始设置：`lagOrder = 2～5 个窗口`、`explainedVariance = 0.95`、`maxComponents = 8`。

> 命名注意：当前代码的 `DynamicPCA` 是"轨迹拼接后的动态滞后矩阵 + 共享 PCA"近似，**不是**严格求解共同主成分协方差联合对角化的 CPCA。原型阶段保留这一可复现近似，但应明确命名；若要声称严格复现 CDPCA，需按各轨迹协方差矩阵实现共同主成分估计并做对照（接口文档 TASK P2 要求两者分开命名、分开消融）。

### 3.6 遗传算法与 HI 构建

**融合模型**：对保留的主成分得分稳健缩放并统一方向后加权：

```text
HI_raw(t) = Σ w_j × PC_health_j(t)，  w_j >= 0，Σw_j = 1
```

个体不直接保存受约束权重，而保存长度为 k 的实数基因 `a`，经数值稳定的 softmax 映射为权重（天然满足约束，无需修复不可行个体）。工程内置轻量实数编码 GA（选择、交叉、变异、精英保留），不依赖 `deap`。

**轨迹级综合优化目标**：

```text
J = λ1 × normalized_MAE(HI, HI_true)     0.30  真值误差
  + λ2 × (1 - monotonicity)              0.20  单调性
  + λ3 × (1 - trendability)              0.15  趋势性
  + λ4 × noise_sensitivity               0.10  噪声敏感性
  + λ5 × cross_run_inconsistency         0.10  跨轨迹一致性
  + λ6 × cross_component_crosstalk       0.10  跨部件串扰
  + λ7 × complexity_penalty              0.05  权重复杂度
```

**指标定义**：

- `monotonicity`：HI 差分为下降方向的比例，允许小死区忽略微小噪声；
- `trendability`：各退化轨迹 HI 与真值退化量之间相关性的中位数（实现修正后为轨迹内 HI 与归一化时间的相关性，避免与真值误差重复使用标签）；
- `noise_sensitivity`：原始 HI 相对因果平滑趋势的残差强度；
- `cross_run_inconsistency`：不同倍率、循环和噪声条件下，按相对退化进度对齐后的 HI 差异（实现修正后为轨迹插值到统一寿命轴后的两两相关性）;
- `cross_component_crosstalk`：本部件模型在其他部件退化轨迹上产生的虚假 HI 下降；
- `complexity_penalty`：同时抑制完全平均和单主成分塌缩，使权重保持中等稀疏度。

GA 参数建议：population 80、generations 120、交叉 0.70、变异 0.20。GA 只在训练轨迹上优化；测试轨迹真值只用于最终评价。

### 3.7 HI 标定、平滑与等级输出

**标定**（用训练数据）：

```text
HI = clip((score - score_bad) / (score_healthy - score_bad), 0, 1)
```

`score_healthy` 取健康训练窗口稳健高分位；`score_bad` 取训练集中最退化部分的稳健低分位；若后续获得物理失效阈值，应替代数据集最差分位点。

**在线平滑**：因果指数移动平均 `HI_smooth(t) = α×HI(t) + (1-α)×HI_smooth(t-1)`（α=0.20）。不使用依赖未来样本的双向滤波；离线报告可另绘非因果平滑曲线用于观察。

**健康等级**：健康等级阈值只能利用健康数据分位数、仿真真实退化因子和部件失效边界联合标定，不能只凭经验设置。没有物理失效边界前，`HI=0.8/0.6/0.4` 等经验值只能作为实验阈值。

## 4. 部件级路线 B：Autoencoder—GMM（AE-GMM）

**定位**：第一版主算法候选之一，不要求大量故障样本，适合项目早期。流程：

```text
轨迹级划分 → 仅健康轨迹拟合稳健标准化 → 原始多通道窗口
→ 小型Conv1D Autoencoder → 健康潜变量标准化
→ BIC选择GMM成分数 → 负对数似然异常分数
→ 健康校准轨迹分位数映射HI → 因果EMA平滑
→ 三折轨迹级验证、单高斯/重构误差消融和跨部件串扰矩阵
```

基本方法步骤：

1. **仅使用健康工况数据**训练 Autoencoder（编码器/GMM 不读取退化标签）；
2. 通过编码器提取健康状态的低维特征；
3. 用健康样本的低维特征训练 GMM（BIC 选择成分数）；
4. 计算实时样本相对于健康分布的负对数似然或马氏距离；
5. 将异常距离归一化并反向映射为 HI（健康校准轨迹分位数映射）；
6. 对 HI 曲线做因果 EMA 平滑。

建议方向（接口文档 TASK P3）："工况条件化 Autoencoder-GMM"——将任务阶段、推力指令和环境温度等作为条件输入，降低工况变化引起的误报警；比较原分位数、保序回归、工况条件化和非目标对比校准等标定方案。

**互补性结论**：CDPCA-GA 回归好但漏检多；AE-GMM 检出好但 HI 量值和定位差。接口文档 TASK P1 据此规划了"双通道决策层"：CDPCA-GA 提供连续退化 HI 和解释性贡献，AE-GMM 提供突发异常证据、数据质量和快速检测，决策层输出 `component_hi`、`fault_score`、`alarm_state`、`confidence`、`source_flags`；连续 HI 不得因 AE 单次异常直接塌缩，突发报警可用 AE 异常证据旁路触发。

## 5. 实现中的修正记录与已知问题

### 5.1 已修正的问题（相对论文原设计）

1. 跨部件串扰项原直接对未标定的主成分加权值计算报警，量纲不成立；现用与目标部件相同的健康/退化分位点映射成 HI 后再计算串扰。
2. 复杂度项原实际惩罚低熵权重，与"防止权重过度分散"含义相反；现改为同时抑制完全平均和单主成分塌缩。
3. 趋势性原用预测 HI 与 HI 真值的相关性，和真值误差重复使用标签；现改为轨迹内 HI 与归一化时间的相关性。
4. 跨轨迹一致性原只计算绝对幅值标准差；现改为轨迹插值到统一寿命轴后计算两两相关性。
5. 健康样本原按文件顺序轮转分折，恰好将 cycle 与 fold 绑定形成工况混淆；现按 cycle 层内分配健康轨迹，退化轨迹仍按整轨迹留出。
6. 置信度和可观测度原恒为 1；现依据窗口有效数据比例生成质量分数、置信度和质量状态，并输出健康等级及前三个特征贡献。
7. 增加了数据审计 JSON、逐窗交叉验证预测、跨部件报警率和等权 CDPCA 消融基线；模型摘要保存 GA 收敛历史和特征相关性得分。

### 5.2 仍需注意的问题

- **HI 真值是相对标尺**：依据仿真退化参数分位点得到，不是经过物理失效判据确认的绝对健康度；0.8 等阈值目前只能作为统计报警阈值。
- **选择偏差风险**：特征选择、PCA 维数和 GA 目标仍在同一训练折内确定；数据增加后应采用嵌套轨迹级交叉验证或独立验证集。
- **定位混淆**：管路与阀门、燃烧室与喷管共享较多测点，单部件 HI 可能发现异常但不能可靠定位；必须查看完整的"真实退化部件 × 报警模型"混淆矩阵。
- **只建模 phase_2**：适合稳态动力段原型，不能代表起动、关机和全任务阶段；后续应使用分阶段模型或工况条件化残差。
- **频域特征受限**：10 Hz 算法采样下的频域特征只能描述慢变化和控制波动，不能替代泵、涡轮等旋转机械的高频振动特征。
- **仿真逆映射风险**：全部数据来自同一仿真模型时，模型可能只是学习仿真器的逆映射；最终测试应增加模型失配、传感器偏置/漂移/丢包、突变与复合退化、未见任务剖面。
- **CDPCA 命名**：当前实现是动态滞后 PCA 近似，严格联合对角化 CDPCA 需另做消融（见 §3.5）。

### 5.3 验证口径（不可违反）

所有划分以 `run_id` 为最小隔离单位，同一轨迹的窗口不得跨训练集和测试集。模型输入只使用 telemetry；P1—P17、`target_factor` 和 HI 真值只用于训练标定与离线评价。结论应同时报告目标部件误差、健康误报率、非目标退化串扰率和折间离散程度，不能只给训练集 MAE。

## 6. 系统级健康评估

在部件 HI 稳定后再开展系统级融合。当前实现为七节点状态包（每个系统窗口必须恰好包含七个部件，按 `(run_id, time)` 精确内连接，不插值、不前向填充）。

### 6.1 透明融合基线（四种）

| 方法 | 公式/说明 | 特点 |
|---|---|---|
| 等权算术平均 | HI 均值 | 最简单基线，误报最稳 |
| 弱链最小值 | `HI_system = min(HI_1..HI_n)` | 保守、检出快，但单一偏低部件直接拖低系统 HI，健康误报明显 |
| 几何平均 | HI 乘积开 n 次方 | 对偏低部件敏感度介于等权与弱链之间 |
| 熵权加权 | 以退化量 `1-HI` 计算信息熵定权 | 客观赋权对照；只在 train 拟合并冻结应用到 test |

透明方法只接收七部件 HI；`confidence` 作为可追溯质量字段保留，不参与主融合权重和主报警判定。

### 6.2 神经系统级候选（MLP / 仅GAT / Temporal-GAT）

**Temporal-GAT 结构**（`temporal_gat_v1`）：将系统表示为图——节点为七个关键部件，边为固定物理功能连接（液氧泵—氧涡轮、液氧泵—燃烧室、煤油管路—煤油主阀、煤油主阀—燃气发生器、煤油主阀—燃烧室、燃气发生器—氧涡轮、燃气发生器—燃烧室、燃烧室—喷管，另加各节点自环）。输入严格限定为：七部件 HI、HI 一阶差分、七项可用工况（循环编号、噪声水平、氧/燃流量、氧/燃压力、环境压力）及节点身份编码。每个节点先由 24 维 GRU 编码时间状态，再经过两层三头 GAT（每头 24 维）和注意力图级池化，输出逐窗系统 HI。模型共 12,218 个可训练参数（低于 10 万参数约束）。

**隔离边界**：P1—P17、`hi_true`、`system_health_proxy_gt`、模式、目标部件和故障注入时刻不得进入网络输入；`system_health_proxy_gt` 只作为监督目标和离线评价标签。工况中心和尺度只由训练轨迹拟合。

**GAT 节点输入建议**（研究报告）：`[HI, 异常分数, HI变化率, 置信度, 数据质量, 当前工况, 故障诊断概率]`，不建议只有一个 HI。

**对照与消融**（阶段 7，同一 225 train/56 val/128 test 轨迹、相同输入、损失、优化器、早停和 0.80 阈值）：等权、弱链、几何、熵权、MLP、仅时间 GRU、仅逐窗 GAT、完整 Temporal-GAT、等参数随机图（12,218 参数、相同边数、只改拓扑）。

### 6.3 健康等级与预警机制

在连续 HI 基础上划分工程健康等级：健康、轻度退化、中度退化、严重退化、临近失效。预警模块要求：

- 连续超过阈值若干窗口后再触发报警（当前：进入阈值 0.80，连续 3 个窗口越限确认）；
- 设置不同的进入阈值和退出阈值，防止报警抖动（迟滞）；
- 计算 HI 变化率、检测退化起始点和加速点；
- 输出结果置信度或置信区间；
- 缺少物理失效时刻时不计算虚假的提前预警时间。

## 7. 验收指标体系

### 7.1 指标维度

- **部件 HI 质量**：MAE、RMSE、R²、Pearson/Spearman；趋势性、单调性、鲁棒性、跨轨迹一致性、早期微弱退化敏感性；健康轨迹 HI 均值/标准差/低分位点。
- **预警性能**：误报警率（窗口/轨迹两种）、漏报警率、退化起始检测延迟、相对失效时刻的提前预警时间、报警抖动次数、不同严重度下的检测率。
- **泛化性能**：未见环境温度/负载/退化速率/随机种子、不同传感器噪声与漂移、数据缺失、单故障训练复合故障测试、模型失配。
- **工程性能**：单窗口推理时间、内存/资源占用、实时吞吐、数据缺失降级运行、置信度校准、模型版本可追溯。
- **消融试验**（证明 GA 和动态特征确实带来收益）：单一敏感信号均值 / 手工特征等权融合 / 静态 PCA 等权 / CDPCA 等权 / CDPCA+GA / 去串扰惩罚，共 6 档对比。

### 7.2 固定验收目标（已冻结）

| 验收项 | 目标 |
|---|---:|
| 数据有效率 | 100% |
| 健康场景误报率 | 不高于 5% |
| 单部件退化HI MAE | 不高于 0.10 |
| 单部件退化HI R² | 不低于 0.75 |
| 单部件退化HI ±0.10命中率 | 不低于 70% |
| 突发故障检出率 | 不低于 90% |
| 突发故障中位检测延迟 | 不高于 12 s |
| 非目标部件串扰率 | 不高于 10% |
| GAT图结构增益 | 多个留出折稳定优于同输入MLP或最强透明基线 |

所有 HI 指标只相对于部件代理标签或 `system_health_proxy_gt`，不得解释为真实物理安全裕度。

## 8. 当前实测结果（截至 2026-09-07 报告）

## 9. 当前结论、候选与边界

### 9.1 当前候选方案

- 部件 HI 回归：**冻结 CDPCA-GA**；
- 部件突发故障证据：**冻结 AE-GMM**；
- 系统非透明候选：**仅 GAT 或 MLP**；
- 系统透明候选：**等权或几何融合**；
- 完整 Temporal-GAT：探索性保留，不是优先提升对象。

### 9.2 目标差距摘要（对应 §7.2 目标）

| 实验 | 方法 | 健康误报 | 退化MAE | 退化R² | ±0.10命中 | 串扰 | 故障检出 | 延迟 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 冻结外部 | CDPCA-GA | 6.5% | 0.060 | 0.888 | 79.9% | 11.7% | 61.9% | 4.9 s |
| 冻结外部 | AE-GMM | 3.5% | 0.193 | 0.295 | 48.7% | 26.3% | 93.7% | 1.2 s |
| 409重训练 | CDPCA-GA | 15.7% | 0.092 | 0.668 | 65.1% | 24.6% | 76.2% | 12.8 s |
| 409重训练 | AE-GMM | 10.3% | 0.314 | -1.986 | 25.5% | 27.2% | 95.2% | 12.9 s |

系统层：仅 GAT 和 MLP 回归与误报较好但故障检出未达 90%；几何融合检出达标但健康窗误报 5.2% 略高且传感器虚降 14.3%。改进方向见 [05_工作进程与任务对照.md](05_工作进程与任务对照.md) 的 P0—P6 任务看板。

### 9.3 边界声明（所有结论的统一限定）

- 所有 HI 指标只相对于部件代理标签或 `system_health_proxy_gt`；该标签由部件因子构造（七部件健康代理取最小值），**不是**独立的物理性能裕度、推力裕度、任务成功概率或真实失效边界。
- 弱链融合与该代理标签在数学结构上同为最小值，其相对优势不能解释为更接近真实物理安全裕度。
- 只有获得独立物理裕度、试验测量或经确认的系统安全标签后，才能把结论升级为真实物理安全裕度或剩余寿命判断。
- 数据集为仿真生成，适合验证算法流程与鲁棒性，不应直接作为工程性能结论的唯一依据。
