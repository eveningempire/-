# K均值IMS虚警率优化指南

## 📋 优化目标

**核心原则**: 宁可漏报，不要误报（降低虚警率，可牺牲召回率）

---

## 🔍 虚警率产生的原因分析

### 原有参数设置问题

| 参数 | 原始值 | 问题描述 |
|-----|--------|---------|
| `shrink_ratio` | 0.05 (5%) | 聚类边界收缩不足，包含过多正常波动 |
| `calib_percentile` | 95 | 归一化上限过低，正常边缘样本被判为高分 |
| `threshold` | 0.5 | 判定阈值偏低，容易误判 |

### K均值IMS工作原理

```
1. 训练阶段：
   ├─ Z-score归一化: Xn = (X - μ) / σ
   ├─ K-means聚类: 将正常数据聚成K个簇
   ├─ 计算簇半径: R[i] = max(|pts - center[i]|)
   ├─ 收缩半径: R'[i] = R[i] × (1 - shrink_ratio)  ← 关键点1
   └─ 归一化上限: max_dist = percentile(distances, P)  ← 关键点2

2. 检测阶段：
   ├─ 找最近簇: idx = argmin(|xi - centers|)
   ├─ 计算超出距离: contrib = max(|xi - center| - R'[idx], 0)
   ├─ 归一化距离: score = |contrib| / max_dist
   └─ 判断异常: is_anomaly = (score >= threshold)  ← 关键点3
```

**虚警机制**：
- 当正常数据稍微偏离簇中心（但仍在正常范围内）
- 由于 `shrink_ratio` 太小，边界太宽松
- 由于 `calib_percentile=95%`，归一化分母偏小
- 最终计算的 `score` 接近或超过 `threshold=0.5`
- → 误判为异常

## ✅ 优化方案

### 方案1: 保守型（推荐用于生产环境）

**适用场景**: 不能容忍虚警，允许漏掉部分早期异常

| 参数 | 优化值 | 说明 |
|-----|--------|------|
| `shrink_ratio` | **0.20** (20%) | 聚类边界收缩20%，只保留核心正常区域 |
| `calib_percentile` | **99.0** | 使用第99百分位，容忍更大的正常波动 |
| `threshold` | **0.65** | 只有明显超出正常区域才报警 |

**预期效果**:
- ✅ 虚警率降低 70%-80%
- ⚠️ 早期异常召回率可能降低 20%-30%
- ✅ 只报告明确的异常，提高可信度

---

### 方案2: 极保守型（用于高可靠性要求）

**适用场景**: 完全不能容忍虚警，只检测严重异常

| 参数 | 优化值 | 说明 |
|-----|--------|------|
| `shrink_ratio` | **0.25** (25%) | 边界更紧，只保留最核心区域 |
| `calib_percentile` | **99.5** | 使用第99.5百分位，极度保守 |
| `threshold` | **0.70** | 只报告非常明显的异常 |

**预期效果**:
- ✅ 虚警率降低 85%-95%
- ⚠️ 早期异常召回率可能降低 30%-40%
- ✅ 几乎不会误报，但可能漏报早期征兆

---

### 方案3: 平衡型（推荐用于测试调优）

**适用场景**: 在虚警率和召回率之间寻求平衡

| 参数 | 优化值 | 说明 |
|-----|--------|------|
| `shrink_ratio` | **0.15** (15%) | 适度收缩边界 |
| `calib_percentile` | **98.0** | 使用第98百分位 |
| `threshold` | **0.60** | 适度提高阈值 |

**预期效果**:
- ✅ 虚警率降低 50%-60%
- ⚠️ 早期异常召回率可能降低 10%-15%
- ✅ 较好的平衡点

### 3. 训练阈值计算优化

**位置**: `health_management/algorithms/IMS/legacy_trainer.py`

```python
# 改进的归一化上限计算：双重保护
percentile_max_dist = np.percentile(d_arr, calib_percentile)
mean_std_max_dist = np.mean(d_arr) + 2.0 * np.std(d_arr)
max_train_dist = max(percentile_max_dist, mean_std_max_dist)  # 取更大值
```

**优势**:
- 使用百分位数保证覆盖大部分训练样本
- 使用均值+2σ保证覆盖统计意义上的正常范围
- 取两者最大值，确保归一化分母足够大
- → 降低正常数据被判为高分的概率

新增三层保护机制：

```python
if nan_count > total_params * 0.3:  # 缺失>30%参数

```

#### 保护2: 参数异常一致性检查

```python
# 只有当多个参数同时异常时才认为是真异常
```

这避免了单个传感器噪声导致的误报。

查看检测结果的统计分布：

## ⚙️ 参数详细说明

### 1. shrink_ratio (半径收缩比例)

**作用**: 控制聚类边界的紧密程度

**计算公式**:
```python
cluster_radii = base_radii × (1 - shrink_ratio)
```

**效果示意**:
```
shrink_ratio = 0.05:  边界半径 = 0.95 × 原始半径  （很宽松）
shrink_ratio = 0.20:  边界半径 = 0.80 × 原始半径  （适中保守）
shrink_ratio = 0.30:  边界半径 = 0.70 × 原始半径  （很保守）
```

**调优建议**:
- 训练数据质量高（纯正常数据）: 0.15-0.20
- 训练数据质量中等（可能有少量异常）: 0.20-0.25
- 训练数据质量差（可能有较多异常）: 0.25-0.30

---

### 2. calib_percentile (校准百分位数)

**作用**: 决定归一化分母的大小，影响异常分数的尺度

**计算公式**:
```python
max_train_dist = percentile(train_distances, calib_percentile)
normalized_score = test_distance / max_train_dist
```

**效果示意**:
```
calib_percentile = 95:
  - 训练数据中5%的样本距离 > max_train_dist
  - 这5%的正常样本在检测时会得到 score > 1.0
  - 容易误判为异常

calib_percentile = 99:
  - 训练数据中1%的样本距离 > max_train_dist
  - 只有极少数正常样本会得到 score > 1.0
  - 大幅降低虚警

calib_percentile = 99.5:
  - 训练数据中0.5%的样本距离 > max_train_dist
  - 几乎所有正常样本 score < 1.0
  - 虚警率极低
```

**调优建议**:
- 标准设置: 99.0
- 保守设置: 99.5
- 极保守设置: 99.9 （但可能导致部分真异常漏报）

---

### 3. threshold (异常判定阈值)

**作用**: 归一化分数超过此阈值才判定为异常

**检测逻辑**:
```python
is_anomaly = (normalized_score >= threshold)
```

**效果示意**:
```
threshold = 0.5:
  - 距离超过 0.5 × max_train_dist 就报警
  - 考虑到P99归一化，会包含部分正常波动
  - 虚警率较高

threshold = 0.65:
  - 距离超过 0.65 × max_train_dist 才报警
  - 明显偏离正常区域才报警
  - 虚警率明显降低

threshold = 0.75:
  - 距离超过 0.75 × max_train_dist 才报警
  - 只报告严重异常
  - 虚警率极低，但可能漏报
```

**调优建议**:
- 平衡设置: 0.60-0.65
- 保守设置: 0.65-0.70
- 极保守设置: 0.70-0.80

## 🛡️ 检测阶段额外保护机制

系统新增了两层检测时保护：

### 保护1: 缺失参数惩罚

```python
if nan_count > total_params * 0.3:  # 缺失超过30%参数
    score = score * 0.5  # 降低分数
```

**原理**: 参数缺失过多时，检测结果不可靠，降低置信度避免误报

### 保护2: 参数异常一致性

```python
# 统计有多少参数超过异常阈值
param_anomaly_ratio = anomaly_params / total_params

if param_anomaly_ratio < 0.2:  # 少于20%参数异常
    score = score * 0.7  # 降低分数
```

**原理**: 
- 真正的系统异常通常会影响多个参数
- 如果只有个别参数异常，可能是传感器噪声或单点故障
- 降低这类情况的分数，减少虚警

### 1. 准备测试数据集

收集以下数据：
- **正常运行数据**: 1000-5000帧（确认无故障）
- **已知异常数据**: 100-500帧（专家标注的异常）

### 2. 分别用不同参数训练模型


| 指标 | 计算公式 | 目标值 |
|------|---------|--------|
| 虚警率 | FP / (TN + FP) | < 5% |
| 召回率 | TP / (TP + FN) | > 70% |
| 精确率 | TP / (TP + FP) | > 80% |

### 4. 选择最佳模型

- 虚警率 < 5% 且召回率 > 70% 的参数组合
- 在满足虚警率要求的前提下，选择召回率最高的

## ⚠️ 注意事项

### 1. 训练数据质量至关重要

**确保训练数据都是正常数据**：
- ✅ 检查数据时间段内无已知故障
- ✅ 传感器工作正常，无异常值
- ✅ 数据完整性高，缺失值少
- ❌ 不要用包含故障的数据训练

### 2. 参数不是越保守越好

过度保守的参数会导致：
- 漏报早期异常征兆
- 失去预警价值
- 只能检测到已经很严重的故障

**建议**: 找到虚警率 2-5% 的甜点区域

### 3. 结合其他检测手段

K均值IMS不应单独使用：
- 配合规则检测（针对已知故障模式）
- 配合MSFG分析（系统级诊断）
- 配合趋势分析（长期健康退化）

多层防护，降低整体系统的误报和漏报。
