# 系统扩展与批量数据处理设计说明

## 1. 模块化扩展方式

平台按数据集、故障诊断、健康评估、寿命预测和算法资产五个边界组织。新算法通过独立应用或适配器接入，在路由层保留统一的 JSON 入口，在结果层返回算法名称、运行模式、数据质量和证据字段。这样可以在不修改已有页面的情况下增加算法版本；部署到离线电脑时只需把算法资产放入 `integrations/algorithm_assets`，并在对应适配器中注册。

当前批处理入口：

| 能力 | 接口 |
| --- | --- |
| 数据文件预检 | `POST /api/v1/datasets/inspect/` |
| 数据文件批量导入 | `POST /api/v1/datasets/batch-import/` |
| 批量故障诊断 | `POST /api/v1/fault-diagnosis/batch-predict/` |
| 批量寿命预测 | `POST /api/v1/rul/predict/`，请求体使用 `dataset_ids` |
| 参数文件批量校验 | `POST /api/v1/integrations/algorithm-assets/parameters/batch/` |

## 2. 大规模数据处理流程

1. 通过“数据集构建和管理”选择多个 CSV、JSON、JSONL 或 XLSX 文件。
2. 系统按文件流读取表头和数据行，统计行数、数值列、缺失值、非法值，并根据文件名和列名推断系统、部件和故障类别。
3. 预检结果按文件返回，管理员可以先修正质量为 `warning` 或 `error` 的文件。
4. 批量导入接口逐文件保存数据集，单个文件失败不会回滚其他文件；每个文件返回数据集编号和质量报告。
5. 诊断、健康评估和寿命预测使用数据集编号进行分批处理，结果带有 `dataset_id`，便于追溯原始文件。

为避免离线电脑内存占用过高，单次批量导入上限为 2000 个文件，批量诊断为 200 个数据集，批量寿命预测为 100 个数据集。更大的任务应由客户端分批提交；后续接入任务队列时可以保持相同请求格式。

## 3. 故障诊断判定标准

每个诊断结果都包含：

- `decision`: `normal`、`abnormal` 或 `uncertain`；
- `decision_label`: 面向用户的中文判定；
- `confidence`: 算法给出的最高类别置信度；
- `evidence` 或 `window_series`: 测点基线、当前值、Z 值、窗口类别等证据；
- `data_quality`: 行数、数值列、缺失值和非法值统计。

统一判定规则是：算法输出正常类别时判定为正常；输出故障类别且置信度不低于 0.55 时判定为异常；类别未知或置信度低于 0.55 时判定为诊断不确定。MSFG + TEAMS-RT 使用基线均值和标准差计算测点偏离，PCA-iForest 使用窗口特征偏离和孤立森林，Hier14 优先调用 health-main 模型，运行依赖缺失时使用明确标注的 fallback 结果。

## 4. 参数文件批处理

参数处理支持 CSV、JSON、JSONL、YAML 和 YML。系统会统一展开嵌套字段、转换布尔值和数值、检查空值、非有限值及明显超范围值，并返回成功、警告、失败文件清单。每个文件最多返回 100 条标准化记录用于预览，完整文件仍保留在原始位置。

后续系统改造可按以下顺序进行：

1. 为不同算法登记参数模式和单位；
2. 在校验器中加入必填字段、枚举值和物理范围；
3. 将批处理提交改为任务队列，增加任务编号、进度和断点续跑；
4. 将标准化参数写入版本化算法资产，并记录操作者、时间和输入文件哈希；
5. 在模型注册页面增加“参数版本—模型版本—数据集版本”关联。
