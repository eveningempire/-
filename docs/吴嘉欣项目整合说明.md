# 吴嘉欣项目成果整合说明

## 1. 整合目标

本次以现有 `phm_platform` 为唯一主工程，把 `吴嘉欣_SY2424110` 中可复用的航天器结构、故障知识、算法模型和 Simulink 仿真成果接入统一的 Django + Vue PHM 平台。原工程不作为第二套服务并行启动，避免路由、数据库、依赖和页面风格冲突。

## 2. 已识别的源项目

源文件实际包含三组成果：

1. `health2_2025_3_19.zip`：Django + Vue 航天器健康评估系统，含结构树、部件档案、遥测、故障注入、诊断、健康评估、FMECA、FTA、多信号流图及权限页面。
2. `health.zip` 与 `RL_learn.zip`：维修辅助决策、健康评估、故障诊断、RUL 预测以及强化学习实验。
3. `simulate/`：火箭动力/控制系统及发射、RCS、气动舵阶段的 MATLAB/Simulink 模型。

## 4. 为什么没有整包复制

源压缩包约数 GB，其中包含 Python 3.9 完整环境、`.venv`、Git 对象、缓存、重复工程和大量训练数据。整包复制会引入以下问题：

- Django/Vue 工程和 URL 重复；
- Vite、Element Plus、Django 和 Torch 版本冲突；
- MySQL 固定账号及明文密码；
- JSON 明文用户密码，不符合权限安全要求；
- 大量固定盘符导致换机器即失效；
- MATLAB Engine 调用阻塞 Django 请求；
- 原始算法接口文件职责过多，难以测试和维护。

因此当前采取“资产迁移 + API 适配 + 页面重构”的方式，原项目仍保持不变，可随时核对来源。

## 5. 当前运行边界

- 部件档案、FMECA 和资产目录已经可以通过页面和 API 使用。
- 模型文件已迁入但尚未进行输入维度、归一化参数、PyTorch 版本和输出语义验证，暂不在线推理。
- Simulink 文件已迁入但尚未启动 MATLAB Engine；后续应由独立任务进程执行，并通过任务 API 返回进度与结果。
- FTA、维修决策、故障注入目前完成产品入口和接口位置，原算法仍需经过重构和验证后启用。
- 原项目的用户表与明文密码未迁入；平台继续使用 Django 权限体系。

1. 先建立结构树数据库模型，将 49 个 JSON 档案导入正式表并增加父子层级。
2. 为 FMECA 建立增删改审计及版本管理。
3. 从模型资产中选择一套完整样本链路，验证 `输入数据 → 特征 → 健康度/故障/RUL`。

6. 对迁入算法进行单元测试、性能测试和结果复核后，再把状态从“已登记”改为“可运行”。
