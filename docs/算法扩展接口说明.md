# 算法扩展接口说明

平台提供本地算法插件目录与统一 API。甲方新增算法时，只需在 `integrations/algorithm_plugins` 下建立一个与算法 `key` 同名的目录，放入 `manifest.json` 和 Python 入口文件。保存文件后，算法目录接口会在下一次请求自动发现该算法，无需修改 Django 路由或重新生成数据库迁移。

## 接口

基础路径：`/api/v1/integrations/algorithm-assets/`

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `algorithms/` | 列出内置及已安装插件，可用 `?category=diagnosis` 筛选 |
| GET | `algorithms/{key}/` | 查看算法版本、类别、输入格式和参数定义 |
| POST | `algorithms/import/` | 管理员上传 ZIP 算法包，导入后立即出现在模型管理目录 |
| POST | `algorithms/{key}/run/` | 对一个已登记数据集运行算法 |
| POST | `algorithms/{key}/batch-run/` | 对 1–100 个已登记数据集运行算法，逐个返回结果或错误 |

接口使用现有登录会话。目录和详情需要登录；运行需要 `run_analysis` 权限。POST 请求遵循 Django CSRF 保护，浏览器先访问目录接口获取 `csrftoken` Cookie，再在请求头传入 `X-CSRFToken`。

在页面中，可直接打开“模型与可视化 → 模型管理”，展开“导入模型 / 算法”，选择 ZIP 算法包并点击“导入算法包”。该操作需要管理员权限。ZIP 可以直接包含 `manifest.json` 与入口文件，也可以用一个与 `key` 同名的顶层目录包住所有文件；文件夹内可携带 `.pt`、`.pkl`、`.joblib` 等模型资产。单包上传上限 200 MB、解压后上限 500 MB；已存在的 key 不会被覆盖。导入成功后模型管理列表立即显示“已导入，待验证”，诊断和寿命预测类插件也会进入相应页面的算法选择框；应使用测试数据实际运行后再确认可用。健康评估类插件目前通过统一运行接口调用。

单次运行请求：

```json
{"dataset_id": 49, "parameters": {"threshold": 0.8, "signal": "S1"}}
```

批量请求：

```json
{"dataset_ids": [16, 17, 18], "parameters": {"threshold": 0.8}}
```

返回结构包含 `algorithm`、`category`、`dataset_id`、`status` 和 `result`。批量接口还包含 `total`、`success`、`failed`。单个数据集失败不会中断后续处理。

## 插件清单

运行目录已移除演示插件；下面保留清单格式示例，供新增算法时参考：

```json
{
  "key": "example_pressure",
  "name": "示例：压力阈值诊断",
  "version": "1.0",
  "category": "diagnosis",
  "entrypoint": "algorithm.py:predict",
  "min_rows": 8,
  "parameters": {
    "threshold": {"type": "number", "default": 0.8, "minimum": 0, "maximum": 1000000000},
    "signal": {"type": "string", "default": "S1"}
  }
}
```

`category` 允许 `diagnosis`、`health_assessment`、`rul`。参数类型允许 `number`、`integer`、`boolean`、`string`；可设置 `required`、`default`、`minimum`、`maximum`、`enum`。入口函数签名固定为：

```python
def predict(csv_path: str, parameters: dict) -> dict:
    ...
```

诊断算法至少返回 `pred_name` 或 `aggregate_pred_name`；建议同时返回 `confidence`、`evidence`、`window_series` 和 `decision_rule`。健康评估至少返回 `health_index`；寿命预测至少返回 `rul_value` 和 `unit`。结果必须是可序列化的 JSON 对象。插件数据输入当前支持已登记的 CSV 文件；其他格式应先转换成 CSV 或后续扩展输入适配器。

## 正常基线导入

本机正常基线来源是 `integrations/simulation_assets/simulate_data_+1.zip` 中的 `baseline` 目录。运行：

```powershell
.\.venv\Scripts\python.exe manage.py import_baseline_datasets
```

命令会逐行确认 `FaultFlag=0` 且无空字段，再把 7 组原始状态量和 7 组派生参数 CSV 登记到当前数据库。重复执行会跳过已有文件。可先用 `--dry-run` 预检。正常基线是仿真数据，不等同于真实飞行的正常样本。

现有 MSFG + TEAMS-RT 和 PCA-iForest 使用通用测点偏离规则，对这批飞行时序基线可能产生“异常”判定。数据标签仅表示仿真时未注入故障，不能代替模型判定；要用其评估误报率，需要先完成测点映射、工况分段和阈值标定。

## 甲方故障数据导入和字段约定

`simulate_data_+1.zip` 共包含 492 个 CSV（246 组原始状态量/派生参数），其中正常基线 14 个，13 类故障/退化场景 478 个。导入到本平台的数据管理数据库：

```powershell
.\.venv\Scripts\python.exe manage.py import_simulation_datasets --include-baseline --report media/datasets/simulate_data_+1/import_manifest.json
```

可用 `--archive` 指定甲方 ZIP 路径，`--dry-run` 列出待导入文件。正常基线复用现有记录；重复运行校验本地文件和归档内容，字节不一致时停止，避免覆盖已修改文件。导入不改变 CSV 的列名、数值和精度。故障类型由场景目录记录，飞行批次和注入时刻分别来自文件名 `fcN`、`tN`；文件中的首次 `FaultFlag=1` 时刻也记录在校验清单中。

字段角色已由甲方确认：

- `Time`：仿真时间戳，用作图表和诊断窗口时间轴；不作为诊断或健康评估的参数输入。
- `FaultFlag`：故障真值标签，0 为正常，1 为已注入故障；用于统计正常/故障采样点和核对注入时刻，不参与诊断和健康评估特征计算。
- 其余列：参数。原始状态量有 29 列参数，派生文件有 `P1`–`P17` 共 17 列参数。

字段角色识别不区分大小写，也支持 `Fault_Flag`；存储保持源文件表头。数据详情、分页采样、诊断数据质量报告和 ZIP 预览均返回字段角色。数据管理的“查看数据”显示时间字段、故障标签、参数列数、正常/故障点数和首次故障时间戳。

故障事件重演直接读取 CSV，不再将整批仿真样本复制到遥测表。较长曲线每约 2000 个点做展示抽样，保留首末点及故障标签切换位置；抽样只影响展示，完整源文件可下载。`FaultFlag` 保留在明细表中，与参数曲线区分。

## 部署注意事项

插件 Python 文件只应由甲方可信管理员在本机安装。导入接口接受管理员上传的 ZIP 算法包；运行接口不接受代码、模块路径或任意文件路径。插件在平台进程中运行，因此新算法应先在测试环境验证依赖、内存、运行时间和结果格式，再安装到正式电脑。示例压力算法仅演示接入方式，其阈值未经设备标定。
